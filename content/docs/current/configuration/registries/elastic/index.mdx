The `elastic` registry lets you configure the [Elastic Container Registry](https://www.docker.elastic.co/) (`docker.elastic.co`) integration.

Drydock automatically detects `docker.elastic.co` and its subdomains. Lookalike hosts such as `docker.elastic.co.attacker.com` never match, so credentials are only sent to Elastic.

## Variables

| Env var | Required | Description | Supported values | Default value when missing |
| --- | :---: | --- | --- | --- |
| `DD_REGISTRY_ELASTIC_{REGISTRY_NAME}_LOGIN` | ⚪ | Elastic registry username | `DD_REGISTRY_ELASTIC_{REGISTRY_NAME}_PASSWORD` must be defined | |
| `DD_REGISTRY_ELASTIC_{REGISTRY_NAME}_PASSWORD` | ⚪ | Elastic registry password | `DD_REGISTRY_ELASTIC_{REGISTRY_NAME}_LOGIN` must be defined | |
| `DD_REGISTRY_ELASTIC_{REGISTRY_NAME}_AUTH` | ⚪ | Base64-encoded `login:password` string | `DD_REGISTRY_ELASTIC_{REGISTRY_NAME}_LOGIN/PASSWORD` must not be defined | |

## Examples

### Configure for anonymous access

Anonymous access needs no configuration. Drydock detects `docker.elastic.co` images out of the box and fetches an anonymous bearer token from Elastic's token endpoint.

### Configure with login and password

<Tabs items={["Docker Compose", "Docker"]}>
<Tab value="Docker Compose">

```yaml
services:
  drydock:
    image: codeswhat/drydock:1.9.0-rc.1
    ...
    environment:
      - DD_REGISTRY_ELASTIC_PRIVATE_LOGIN=myuser
      - DD_REGISTRY_ELASTIC_PRIVATE_PASSWORD=xxxxx
```

</Tab>
<Tab value="Docker">
```bash
docker run \
  -e "DD_REGISTRY_ELASTIC_PRIVATE_LOGIN=myuser" \
  -e "DD_REGISTRY_ELASTIC_PRIVATE_PASSWORD=xxxxx" \
  ...
  codeswhat/drydock:1.9.0-rc.1
```
</Tab>
</Tabs>

      - DD_REGISTRY_ELASTIC_PRIVATE_AUTH=YOUR_BASE64_AUTH
