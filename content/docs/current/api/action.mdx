`/api/v1/actions` is the action view of the trigger registry. It behaves exactly like the deprecated `/api/v1/triggers` routes (same auth, same response shapes) but only exposes action triggers (`docker`, `dockercompose`, `portainer`, `command`). Any other trigger type returns 404.

## Get all actions

```bash
curl http://drydock:3000/api/v1/actions

{
    "data": [
      {
        "id": "docker.local",
        "type": "docker",
        "name": "local",
        "configuration": { "prune": false }
      }
    ],
    "total": 1,
    "limit": 0,
    "offset": 0,
    "hasMore": false
}
```

## Get a action by id

```bash
curl http://drydock:3000/api/v1/actions/docker/local
```

To fetch one registered on a specific agent, append the agent name: `/api/v1/actions/docker/local/agent1`.

## Running a action

Run an action against a container drydock already watches. Local routes are `POST /api/v1/actions/:type/:name`; for containers managed by a remote agent use `POST /api/v1/actions/:type/:name/:agent`.

The body only names the container by `id` (plus an optional `operationId`). The action runs on drydock's stored copy of that container, so any `image`, `labels`, `result` or other field in the body is ignored. An `id` drydock doesn't know returns `404`.

```bash
export CONTAINER='{"id":"123456789"}'
curl -X POST -H "Content-Type: application/json" -d "$CONTAINER" http://drydock:3000/api/v1/actions/docker/local
```
